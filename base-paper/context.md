# Repository Context

## Purpose
This repository runs multi-agent number-guessing coordination experiments with LLM agents, then stores and analyzes outcomes.

Core research question: whether independent LLM agents can converge on a hidden target through shared scalar feedback (too high / too low / correct).

1. Runtime/game engine

## End-to-End Execution Flow

1. Entry script launches many experiment configurations.
- run_experiment_multi_model.py (or persona_experiment.py)
- builds configuration batches
- runs each batch with bounded concurrency using asyncio.Semaphore

2. Each configuration creates a game instance.
- GameMaster or PersonaGameMaster
- creates results folder structure
- saves config.json

3. Each round runs all agents concurrently.
- each agent builds a prompt
- llm_run.chat sends async API requests with retry + backoff
- responses are parsed into integer guesses

4. Round bookkeeping and persistence.
- round_XX.json written each round
- game_log.txt appended each round
- raw API payload files optionally saved
- prompt snapshots captured in llm_prompts.json for selected rounds

5. Completion outputs.
- summary.json with solved status and final metrics
- CSV export (when generated by the current code path)

6. Offline analysis.
- results_visualization.py aggregates run outcomes and creates PDF plots
- extract_game_data_to_csv.py derives simple per-round CSVs from logs

## Core Concepts

1. Modes
- sum mode: group sum should equal mystery number
- mean mode: rounded group mean should equal mystery number

2. Feedback signal
- too HIGH
- too LOW
- CORRECT!

3. Robustness
- API retry with exponential backoff and jitter
- soft fallback responses on repeated failures
- parsing fallback paths when model output is not cleanly numeric

## Observed Behavioral Characteristics

1. In experiment.py, parsing failures usually do not crash a run.
- fallback behavior reuses prior successful guess or midpoint of range

2. In llm_run.py, soft_fallback=True returns a synthetic OpenAI-like response.
- this lets experiment loops continue even after API failure

3. In persona_experiment.py, parsing behavior is stricter.
- parsing errors are allowed to propagate and may mark config as failed/parsing_failed

4. In experiment.py, raw API response persistence appears to run only for fallback responses due indentation placement in play_round.
